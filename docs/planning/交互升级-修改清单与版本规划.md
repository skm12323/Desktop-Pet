## 1. 调研摘要（2026-10-04）

**渠道**：内置 WebSearch / webReader 当日配额耗尽（10-15 恢复），WebFetch 与
github.com 直连被本机代理掐断；最终经浏览器走必应中国 → Gitee 镜像 →
OSCHina / CSDN 完成。Shimeji / Desktop Mate / Tamagotchi 部分基于既有产品
知识，**10-15 配额恢复后建议复核一轮**（重点：Desktop Mate 现行交互清单）。

### 1.1 VPet（桌宠界功能标杆，实证来源标注）

| 机制 | 证据 | 对本产品的启示 |
|---|---|---|
| 摸头 = **鼠标划过触发**（非点击） | Gitee 镜像 commit "支持移动摸头" | 直接操纵优于菜单按钮；划过即反馈是"活物感"的关键 |
| 互动动词：触摸 / 喂食 / 送礼 | CSDN 综述 | 动词要以宠物为中心设计（送礼是后置项，见 §5） |
| 动画矩阵 32 种 × 4 状态 × 3 类型 | OSCHina 项目页 | 反馈多样性的量级参照——"每种交互有专属反馈"是底线，量级不追 |
| 互动例子：摸头 / 提起 / 爬墙 | OSCHina 项目页 | 全是直接操纵型；菜单只是辅助入口 |
| **互动疲劳**（"避免过度互动导致宠物疲劳"） | CSDN 综述 | 拒绝/冷却机制的推广形式：防刷数值，也是活物感来源 |
| 节日 / 生日响应（照片图库带玩家生日、七夕标签） | Gitee 镜像 commit | 低成本高情感收益的惊喜点，纳入 0.19.4 |
| 创意工坊可定制：物品/食物/饮料、说话文本、主题 | OSCHina 项目页 | "说话文本可定制"→ 气泡文案池 config 化；物品生态=后置方向 |

### 1.2 其他参照（既有知识，未当日实证）

- **Tamagotchi / Pou 谱系**：核心循环 = 宠物主动呼叫需求 → 玩家响应 → 多通道
  即时反馈（动画+声音+飘字+表情）。需求可见性前置是留存引擎。
- **Shimeji**：行为自主（爬窗边/掉落/漫游），菜单只是行为触发器之一。
  我们的 FSM（WALK/CLIMB/THROWN/WANDER）底子已备，缺"行为与需求挂钩"。
- **Desktop Mate**：3D 直接操纵、部位级抚摸、给物品——交互语义按 3D 标准
  设计的依据（见 §6 契约）。
- **OS 托盘惯例**（Dropbox/Discord）：托盘 = 状态 + 控制面；图标徽标 /
  tooltip 承载状态。我们的 `set_tooltip` 已支持但闲置。

### 1.3 调研 → 设计原则

1. **能直接操纵的不进菜单**（划过摸头 > 单击摸头 > 菜单动作）。
2. **每种交互至少三通道反馈**：动画 / 飘字+数值 / 文案（音效第四通道跟上）。
3. **宠物要有意见**：饱和拒绝、疲劳冷却——拒绝也是反馈。
4. **动词以宠物为中心**：人"逗猫"优于人"戳猫"；表述换掉占位动词（§4.2）。
5. **简单优先**：不依赖新美术资产的项排前，资产依赖项一律后置（§5）。
6. **交互语义按 3D 可表达的标准设计，2D 阶段降级实现**（§6 契约）。

## 4. 分版本明细

### 0.19.0 交互表现层（快赢）

**F1 数值飘字 HUD**
- 新建 `pet/floating.py`：`FloatingTextWidget`，形态仿 `pet/bubble.py`
  的 BubbleWidget（无框置顶 QWidget + QPropertyAnimation）。
- 触发点：`_interact`（`app.py:1280`）`store.update` 后，头顶飘出
  `饱腹 +20` 类文本，上飘+淡出 ~1.2s；负增量红色下沉。
- 验收：全部交互均触发；连续交互不叠死（复用单实例+重启动画或队列丢弃）；
  跟随宠物移动（复用 `bubble.follow` 的 `_on_pet_moved` 通道 `app.py:1267-1268`）。

**F2 喂食专属动画**
- 复用吃鼠标咀嚼循环帧源（`app.py:1647-1709`）：喂食成功后覆盖播放
  ~1.5s 咀嚼，**不进 FSM 状态**（presenter 层临时帧覆盖，播完还原），
  避免搅动吃鼠标会话逻辑。
- 同法给摸头（眯眼帧，若无素材则本项只做喂食）。
- 验收：喂食必播；播放期间拖拽可打断并正确还原表情（参照 v0.16.12
  的动作帧中断恢复机制）。

**F3 气泡文案模板池**
- `_INTERACT_MSG`（`app.py:108-113`）从 `dict[str, str]` 升级为
  条件模板：交互 × 宠物 mood 区间（happy/neutral/sad）取池随机。
- 池内容 config 可覆盖（`interaction.messages`），延续现有 config 风格。
- 验收：同一交互连续触发文案有变化；config 缺省时内置池兜底。

**F4 音效管线**
- config 新增 `sound` 段：`{enabled: false, volume: 0.6}`（保守默认关）。
- `QtMultimedia.QSoundEffect`；`import` 必须 try/except 降级（缺模块则整层
  静默关闭，与 render3d"永不外抛"哲学一致）。
- 资产位 `assets/sounds/`（吃/摸/梳/逗/拒绝 5 个短音）；**资产缺失只铺
  管线不阻塞版本**，资产后补。
- 验收：开关即时生效；无资产/缺模块零副作用；音效与 F1-F3 同帧触发。

### 0.19.1 动词重表述 + 活物感最小集

**F5 占位动词换代**（显示层换词，信号键 feed/clean/poke 不动——最小改动）
- 现占位：喂食 / 洗澡 / 戳一戳。问题："洗澡"在桌面表现力弱（需水/泡泡
  素材）、"戳一戳"是人自我中心的动作且为唯一负增益（用户摸索出"别碰它"）。
- 新方案（贴猫宠设定、零新素材）：

| 信号键（不变） | 旧表述 | 新表述 | 数值语义 | 表现（复用现有帧） |
|---|---|---|---|---|
| pet | （单击摸头） | 摸摸头 | mood +5（不变） | 眯眼帧/小晃动 |
| feed | 喂食 | 喂点吃的 | fullness +20（不变） | 咀嚼循环（F2） |
| clean | 洗澡 | **梳梳毛** | cleanliness +15（不变） | 眯眼+身体小幅摆动 |
| poke | 戳一戳 | **逗一逗** | mood **+4**（原 -8，见 C1） | 扑咬摆动/兴奋小跳（用现有帧近似） |

- 动词语义："梳毛"是人对猫的自然动作且不暗示水浴场景；"逗"是逗猫棒式
  的以宠物为中心的动作，正面情绪成立。双击=喂食、单击=摸头的快捷语义
  全部不变。
- 改动面：`window.py:480-482` 菜单文字、`app.py:108-113` 文案池、
  config `interaction_gain` 注释与 poke 值、状态板/文档措辞同步
  （`app.py:1008-1039`）。
- 验收：菜单/气泡/飘字/状态板措辞一致；旧 config 的 poke -8 加载时
  被新默认覆盖或迁移提示（config 兼容策略按现有惯例）。

**F6 饱和拒绝**
- 喂食前检查 `fullness ≥ reject_threshold`（config，建议 92）→ 不加数值、
  播拒绝文案池（"吃不下了…"）+ 摇头/扭头类现有帧；**拒绝也是反馈**，
  走完整三通道（飘字显示"饱了"而非数值）。
- 验收：双击狂点不能无限拉满；拒绝态数值与文案/动画一致。

**F7 互动疲劳**
- 同一交互连续 N 次（config，建议 5 次/10 分钟）后增益衰减至 0 + 疲劳
  文案（"歇会儿再玩嘛…"）；防刷数值，也制造"宠物有意见"。
- 验收：连点 5 次后第 6 次起飘字显示疲劳、数值不变；换一种交互立即恢复。

- 验收：状态变化后下次右键可见标记；菜单结构与 0.17 兼容。

## 6. 3D 契约规约（不排版本，随时生效的设计约束）

1. **交互语义按 3D 可表达标准设计，2D 降级实现**：
   - 摸头 = "头部区域抚摸"语义——2D 用整窗单击近似，3D 落胶囊体部位
     命中（`pet/render3d/hit.py` 占位，D11 后置项）。
   - 喂食 = "物品投递到宠物"语义——2D 用双击/菜单近似，3D 升级为食物
     模型拖到嘴边（依赖 §5 物品化）。
   - 梳毛/逗弄 = "接触/挥动"语义——2D 用整窗菜单近似，3D 可落部位
     （背部梳理、逗猫棒挥动轨迹）。
2. **反馈三通道走统一接口**：动画/飘字/音效在一个入口聚合（0.19.0 先
   内联于 `_interact`，0.19.1 随拒绝/疲劳抽出 `InteractionOutcome` 数据类
   ——gains、rejected、fatigued、animation、sound、message——2D/3D
   双实现可替换）。避免为 2D 立绘替换机制量身设计的反馈在 3D 切换时重做。
3. **与 D10/D11 对齐**：表情与动作平行（反馈动画不占用表情通道）；
   整窗命中语义零成本沿用。
4. **物品表天然 3D 可用**（后置项预留）：`items` 配置的 emoji 字段在 3D
   线可映射为 GLB 资产 id，数据结构不迁移。
