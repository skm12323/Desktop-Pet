## 关键实现决策与规范偏离（均已写入代码注释）

1. **软钳公式连续性修正**（§3.1）：规范原式 `M − d0·exp(−(D−M)/d0)` 在
   D=M 处有 d0 幅度位置跳变，取 `M − d0·(1−exp(−(D−M)/d0))`（边界恒等、
   C1、渐近 M−d0），奇异点消除目标不变。
2. **骨盆下沉几何精确化**（§3.2）：`A_dip·sin²` 是形状近似；实现按
   `dip = max_leg(D_rest − sqrt((r·Ltot)² − dx²))⁺` 逐帧精确解算（r=0.975）。
   基线静止伸展率 99.88% 下，规范 88–95% 导则与 3.5–5px 抬脚不可兼得
   （95% 恒定下沉 ≈32 canvas px 会吞掉全部抬脚预算），取 vault 策略。
3. **摆动相重构**（§3.3）：单段三次贝塞尔无法同时满足零端点速度与内部
   抬升（P1y=P0y、P2y=P3y 时无凸包）；实现 = 端点零速 C1 传输 + `sin²(πu)`
   抬脚 bump，软着陆（dY/du|₁=0）与间隙目标等价达成。另增**趾离地段**
   （τ∈[0.60,0.70)，前掌锚定、仰角 35°→18°）：物理真实的推蹬延续，同时
   消除摆动早期足尖穿地（直接起跳会低于地面 ~21 canvas px）。
4. **腿骨限位放宽**：基线 ±25°/−35°/±10° 容不下 IK 步态解（heel-strike 需
   thigh ≈ −34°、roll 需 foot ±35°、右腿静止内弯 +8.6° 使膝需求更深）。
   新包 spec 放宽为 thigh [−50,45] / knee [−75,15] / foot ±60；求解器读任意
   限位并在规划期自适应（抬脚上限按膝限位推导），饱和经 QA 漂移通道上报。
5. **float64 数学核**（模块 2）：1e-6 px 恒等门槛在 ~1600px 幅值下超出
   float32 量化能力（~1e-4）；关键形态模式全链升 64 位并将权重 f64 重归一
   （f32 行和差 6e-8 × 幅值 ≈ 1e-4 px）。GPU 顶点缓冲仍 f32（写入降采）。
6. **窗口位移协议**：求解器内部维护浮点窗口累加器，呈现层据此 int 落位——
   若按整数量化内部坐标，1.25 px/帧 会被银行家舍入吃成 1.0（每帧 −0.25），
   窗口实际速度系统性低于步态规划，双脚逐步后坠直至顶死限位（实测复现）。
   渲染口径漂移因此恰为 ±0.5 px 舍入下界。
7. **view_yaw 为带符号量**（−45..+45）：规范注释写 0~45，但左向行走需要
   负侧视角驱动蒙皮形态，契约字段语义按连续朝向理解。
