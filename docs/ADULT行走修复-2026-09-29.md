# ADULT 侧身行走修复（2026-09-29）

用户在 `main`（v0.16.6）上指出四个问题：①部件裁剪粘连/剪残；②动作僵硬，与正常人行走大相径庭；③侧身时部件问题更严重；④部分部件异常扭曲，疑为 YOUNG 时期算法不适用于长肢体。本文记录诊断证据与修复过程。证据目录：`spikes/_qa/walk_diagnosis_2026-09-29/`（采集/渲染脚本同目录，原在 `.scratch/diag/` 运行）。

## 1. 诊断

### 1.1 部件（问题 ①③）

侧身图层由 SAM 逐像素切分，遮挡区用程序补全（邻色扩散 `diffuse`、大腿边线外推 `extrude`）。`side_layers.png`：

- tail 根部一大块黑/亮蓝/白涂抹——**每一帧行走都从裙下露出**（`walk_cycle_strip.png`）；
- hair_back 混入裙/袖的深蓝色块；
- 大腿外推成带条纹的"金属管"，leg_r 有透明洞；
- skirt 两个洞 + 一条粘连的深蓝尖片；torso / arm_r 边缘黑色涂抹与碎块；hair_side_r 碎成几块；零散碎片各自生成网格单元。

正面部件由 Qwen 逐件重画（`front_layers.png`），干净得多；仅 hair_back_l/r 顶部硬边矩形、tail_seg2 / tail_tip 几乎为空。

### 1.2 步态（问题 ②）

`capture_walk.py` 在真实呈现器里行走并逐帧记录关节世界坐标。**步态按桌面像素速度运行，窗口越大角色相对步幅越小——运动学必须在实际的 256 窗口下测**（640 窗口测得的步幅偏小，已作废）。

| 指标 | 当前 | 正常人（Perry / Winter 矢状面步态） |
|---|---|---|
| 步频 | 1.6 周期/s（192 步/分） | 同等相对速度约 0.85–0.9（约 105 步/分） |
| 步幅 | ≈ 0.58 腿长 | 1.1–1.4 腿长 |
| 髋活动范围 | −10°～+16°（26°） | −10°～+30°（40°） |
| 摆动期髋曲线 | 双峰（大腿前摆中途后退） | 单调前摆 |
| 膝：触地 / 支撑最小 | 25° / 11°（始终半蹲） | ≈ 5° / ≈ 5° |
| 膝：摆动峰值 | 45–51°，双峰 | 60–65°，单峰 |
| 近侧手臂摆幅 | 18° | ≈ 30–40° |

### 1.3 扭曲（问题 ④）

`tools/mesh_generator.py` 的权重是"到骨骼线段距离的 −2.2 次幂"归一化，网格 28 px 规则方格（为 YOUNG 编写）。`weights.png`：无任一骨权重 ≥ 0.9 的顶点——腿 51%、手臂 61–72%、裙 76%、尾 96%；膝部过渡带从大腿中段延伸到小腿中段（≈ 200 px），弯曲如橡皮管、膝部鼓包。

### 1.4 相互牵连

把腿角放大到正常人范围（`legs_amplified.png`）：远侧大腿从裙侧穿出到腰部以上，露出"金属管"补全，膝部折角——**只调步态会当场穿帮**，须先修权重与部件。

修复顺序：A 权重与网格（纯代码）→ B 侧身部件重画（Qwen 逐件，可见区仍用原画像素）→ C 步态改由人体标准关节曲线驱动。

## 2. A：权重与网格

**改动**（只对显式配置的层生效；不带新字段的层——正面 rig、YOUNG——走原算法，已验证正面 rig 用新旧生成器重生成结果完全相同）：

- `tools/mesh_generator.py`
  - `weights.mode = "chain"`：父→子骨链，每个顶点归属最近链段的骨骼，只在关节二等分线两侧 `blend_px` 内与相邻骨过渡（用最近链段而非无限切线，卷曲的尾巴不会被远处关节误切）。
  - `weights.inner`：单向铰链（膝、肘、踝）的**内侧**（屈曲侧）加宽过渡带，按顶点到链轴的横向距离渐变；过渡主要伸入**父段**（`blend_px`），子段只伸入 `down_px`，使小腿保持笔直。
  - `weights.mode = "skirt"`：腰带归裙根，下摆按高度渐入、按前后分给两根裙摆骨。
  - `min_component_px`：小于阈值的碎片不生成网格单元（不再被骨骼拖着走）。
- `tools/build_side_spec.py`：侧身各层配置（腿/臂网格 14 px，裙/尾 20 px）；spec 透传 `weights / grid_step / min_component_px`。

**调参过程（关键发现）。**

1. 窄过渡带（26 px）在步态中膝窝翻折：膝盖弯到 25° 即翻。
2. 试 2D 对偶复数蒙皮（DQS）——**无改善**（翻折是绕支点的扫掠，不是弦塌缩），已撤回运行时改动。
3. 真正原因：**膝关节支点在腿的前缘**（x 464，腿在该高度 x 390–473，距膝窝 ≈ 87 px）——为让 IK 静止时解出前向膝而刻意前移（画上的腿是锁膝微反弓站姿，膝中心在髋–踝连线后 15–27 px）。移到中线需要改造 IK 与锁脚，故保留支点，改用内侧加宽过渡带吸收膝窝褶皱。
4. 内侧宽度随横向位置变化过陡会在大腿后侧剪切翻折；子段完全刚性又会把扫掠集中到关节线、更早翻折；子段延伸过长则小腿中线弯曲（round2"小腿笔直 ≤ 8°"门禁）。网格搜索（仿真膝弯 0–90°）+ 正式门禁复核后定为：膝 `blend 22 / inner 110 / down 60 / ramp 80`（两腿相同，仿真 70° 起才翻折），踝 `28 / inner(前侧) 60 / down 28`，肘 `18 / inner(前侧) 80`；hair_back 碎片阈值 40 px（200 px 会删掉一块静止可见的 43 px 发丝，造成静止空洞）。

**结果**（`weights_after_A.png`、`walk_hips_knees_zoom_before_after.png`、`legs_amplified_before_after.png`）：

| 层 | 无骨 ≥ 0.9 的顶点：改前 → 改后 |
|---|---|
| leg_l / leg_r | 51% → 10%（膝窝加宽带内） |
| arm_l / arm_r | 61% / 72% → 9% / 8% |
| skirt | 76% → 51%（腰—下摆的纵向过渡带，按设计） |
| tail | 96% → 27% |
| torso / hair_back / apron | 97% / 56% / 53% → 20% / 22% / 24% |

网格 1974 → 3364 顶点（四肢 14 px）。G4 门禁顺带重渲染了 `references/side_rest.png`：24 px 变化（8 px 明显，位于尾/腿/裙一带）——被剔除的碎片原本盖在其他层上，剔除后露出下层；空洞仍为 0，G6 接缝指标与改前逐项相同。

## 3. 变形算法改进（计划 `rippling-orbiting-flurry`：推导 D1–D7 与按形状分配的变形器）

A 之后的深挖结论：单块连续网格在铰链处弯曲，det F = 1 + θ·|∇w|·ℓ（DQS；LBS 一阶相同），支点居中且不翻折时外侧峰值拉伸 ≈ 2——A 把分散扭曲换成了集中扭曲（leg_r σmax 2.18、arm_r 1.98），属结构上限，调参不可越过。改为按形状分配：铰链肢体 = 分段刚体 + 圆盘关节盖；尾/发 = 中心线曲线 + 绳索；裙/围裙 = 笼形 MVC + 覆盖约束；躯干保留链式权重。

**阶段 0 度量工具** `spikes/qa_deform_metrics.py --tag <名>`：步态（120/200 px/s，256 窗口）与人类范围压力姿态（膝 65°、髋 +30/−15、肘 45°）下的翻折、每层 σmax/σmin、网格焊接；结果存 `spikes/_qa/deform_metrics/<名>.json`。

| 标签 | σmax | σmin | 焊接 | 说明 |
|---|---|---|---|---|
| head_before_A | 2.59 | 0.40 | 13 | 仓库原状 |
| after_A | 2.90 | 0.011 | 13* | A：极值更差（*旧口径 92，改严格口径后重测） |
| phase1_components | 2.90 | 0.011 | 7 | 按连通分量建网格 |
| phase1_pivots | 2.49 | 0.011 | 7 | 肘/肩支点居中 |
| phase2_arms | 2.49 | 0.011 | 7 | 手臂分段刚体：arm 各块 σ ≡ 1 |

**阶段 1**：`mesh_generator` 新增 `per_component`（侧身各层开启），分离碎块不再共享顶点；剩余 7 处是同一网格单元内落入两块碎片（单元按块复制但共享整格纹理），代价不值得继续细分。手臂支点居中：`forearm_l` 345→366、`forearm_r` 632→604（原在轮廓线上）、`upper_arm_r` 598→555（原在手臂外 16 px）。

**阶段 2**：`tools/split_hinged_limb.py`，由 `build_side_spec.py::split_hinged` 调用，把 arm_l / arm_r 拆成上臂/前臂/手三块单骨层（z：上 > 中 > 下），关节圆盘两块都复制原画像素。G4 静止复原 256 平均差 0.006/255、空洞 0；全部门禁通过（naturalness、round2 8/8、turn gait 28/28、G6 49/49、App 12/12）。`spikes/_qa/deform_metrics/elbow_zoom.png`：弯肘时圆肘连续、无拉伸无翻折；**同时暴露补全缺失**——近侧前臂抬起后，原被手臂遮住的后发/蝴蝶结处露出背景（透明，未补全），远侧前臂边缘有深色碎点（arm_r 补全杂像素）。按计划留给阶段 6（暴露驱动补全）。

**阶段 2 追加（用户目检 2026-09-29）**：近侧手臂正常；远侧手臂（arm_r）原画大部分被遮挡，拆出来异常偏细，旧 Qwen 补全在组装时变成窄条加深色涂抹。用户用 gpt-image-2.5 生成了左右两条完整手臂（`references/gpt_raw/arm_{l,r}_gpt_s1.png`，白底；Qwen 那次漏画了肩部白色荷叶边）。处理：从图像边缘泛洪去掉近白色背景（荷叶边外有深色描边，不受影响）→ 以手臂"真实外轮廓"（与背景/更下层相邻的边，不含遮挡边）的双向倒角距离加溢出惩罚做相似变换配准（缩放 0.422、旋转 ≈0°），得到 `prep/peel/arm_r_gpt_s1_canvas.png` 及来源记录 `.json`。"可见窄条用原画 + 其余用生成图"会因两者错位约 10 px 出现双层袖口，改为**整条远侧手臂都用生成图**（`build_side_spec.py::limb_source`，保留生成图的抗锯齿 alpha）。代价：静止复原 256 平均差 0.003 → 0.54/255（门禁 ≤6），P99 11.6/255（≤50），空洞 0.04%（≤0.1%）；G6 接缝与全部门禁通过。近侧手臂原画完整可见，未替换。证据：`spikes/_qa/deform_metrics/far_arm_gpt_whole.png`、`arm_reg_overlay2.png`。以后生成用于抠像的部件时改用绿底（#00B140，原画中不含绿色）。
